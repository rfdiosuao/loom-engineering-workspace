# LOOM 2.3.22 更新说明

## 智能体与模型

- 修复 Claude Code 被错误识别为 16 位 Windows 程序、无法启动的问题，统一使用受管 npm 启动入口。
- 当当前文本模型在首次输出前遇到上游 `404`、`5xx` 或临时网络故障时，原生智能体会在同一模型账号内自动切换到最多两个可用文本模型。
- 自动回退兼容 `provider/model` 等中转站常见模型 ID，并在运行记录中保留切换原因。
- 已经开始输出或已经执行工具后不会自动换模型，避免重复执行手机、矩阵或发布操作。
- 模型配置仍会拒绝上游未列出、无可用渠道或不支持工具调用的模型，并给出真实错误，不写入假成功配置。

## 创作

- 修复图片或视频任务快速失败后，页面仍长期显示“正在生成”的轮询竞态。
- 失败、取消和完成状态会立即终止对应轮询，不再持续占用 Bridge。

## 自动更新

- 发布流程新增 Ed25519 私钥与客户端内置公钥一致性门禁；密钥不匹配时构建立即失败，不会发布客户端无法信任的更新包。
- 主品牌和 OEM 品牌分别校验自己的更新公钥，OEM 不会被绑定到 LOOM 主发布密钥。
- 保留 SHA256、官方发布签名、断点续传、静默安装、健康检查和失败回滚完整链路。
- 签名不兼容时提供官方发布页的一次性手动升级入口；完成一次手动桥接后，后续版本恢复自动更新。

## 升级说明

- `2.3.20` 及以上版本可通过应用内更新中心自动升级到 `2.3.22`。
- `2.3.17` 等尚未内置当前更新公钥的旧版本，需要从官方发布页手动安装一次 `2.3.22`；用户配置、模型账号、历史会话、手机配置和本地素材保持不变。
- 中转站返回“无可用渠道”“模型不存在”或服务端 `5xx` 时，LOOM 会自动尝试同账户候选模型，但无法替代上游恢复实际模型渠道。
