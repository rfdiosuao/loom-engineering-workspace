# 2026-05-11 更新日志

> 范围：LOOM 启动器、APKClaw 手机端、安全通道、视觉能力与文档收口。

本次更新继续明确“智能体负责思考和调度，APKClaw 负责手机端执行”的协作边界。只有在调试、兜底或手机端多次执行失败时，智能体才介入更底层的视觉与坐标操作。

## 核心成果

- APKClaw 稳定基线更新至 `versionName=6.26`、`versionCode=860`。
- `/api/lumi/*` 安全通道进入可验收状态，覆盖初始化体检、Agent 主控、图片导入、录屏、视频回传和视觉模式。
- 启动器补充 Device Profile 体检上下文，包括屏幕节点统计、视觉建议和兜底提示。
- 游戏与视觉模式形成 MVP 闭环：优先由 APKClaw Agent 观察，必要时由智能体获取视觉帧并生成带目标与原因的安全动作。
- 手机录屏和视频回传进入工作流，可拉取到 `data/phone-videos/` 用于演示素材或复盘。
- 索引、接口契约、交接文档、能力清单和技术债记录与当前实现对齐。

## APKClaw 手机端

- 保留原生 LAN API，用于基础工具、调试和兼容。
- 高级能力逐步迁移到 `/api/lumi/*`：
  - `/api/lumi/device/profile`
  - `/api/lumi/agent/execute_task`
  - `/api/lumi/media/import_image`
  - `/api/lumi/media/record/*`
  - `/api/lumi/media/videos`
  - `/api/lumi/vision/*`
- Device Profile 返回当前屏幕摘要和视觉提示，帮助启动器判断是否需要视觉兜底。
- 产品通道的图片导入使用 JSON `dataUrl`；旧 multipart 路由仅作为兼容能力保留。
- 提供独立指针接口：
  - `POST /api/overlay/cursor`
  - `POST /api/overlay/cursor/preview`
- 视觉动作安全策略覆盖登录、授权、支付、购买、充值、账号绑定、实名、删除、清缓存、上传日志和退出游戏等高风险目标。

## LOOM 启动器与智能体

- 智能体优先调用结构化手机能力，不直接猜测坐标。
- 设备体检结果进入运行时上下文，供任务规划与失败恢复使用。
- 录屏、视频列表和视频回传使用统一的手机鉴权与错误结构。
- 当手机端能力不可用时，界面和日志应提供可行动的错误原因，不返回假成功。

## 验证重点

- 安全通道鉴权失败时不得继续执行设备动作。
- Device Profile、图片导入、录屏与视频回传均需保留结构化失败原因。
- 视觉兜底不得绕过高风险动作限制。
- 公开交付包不得包含真实令牌、设备地址、用户日志或运行时审计数据。
