# LOOM 2.3.28 更新说明

## 模型配置与上游兼容

- 建立统一模型目录，区分“账号可见”与“协议已验证”，避免把仅出现在目录中的模型误判为可用。
- 统一 Codex、Claude Code 与 LOOM 的模型描述、别名和协议能力，减少配置写入后模型无法调用的情况。
- 对模型不存在、协议接口缺失、上游 503/524 和网络超时提供明确中文原因，并标记是否可以重试。

## 智能体稳定性

- 为智能体运行增加规划、工具调用和终态阶段，暂停、重试、取消、成功和失败状态更加一致。
- 修复模型没有返回最终答复时被误判为成功的问题；事件推送异常时保留真实任务结果并标记降级状态。
- 合并同一次运行的工具调用展示，减少重复步骤和工具卡片刷屏。

## 手机矩阵

- 手机端仍在执行但桌面等待超时时，任务保持“执行状态待确认”，不再直接计为设备异常或任务失败。
- 矩阵设备状态、任务步骤和提示文案同步使用不确定状态，避免出现手机正常执行、工作台却显示假失败。
- 加固手机列表与状态路由，减少多设备配置下的错误设备匹配。

## Agent 安装与首次使用

- Windows Agent 安装完成后验证真实启动入口和版本；入口损坏时恢复旧版本并给出可重试原因。
- 优先识别 `.cmd`、`.exe`、`.ps1` 和 `.bat` 入口，减少 64 位 Windows 把无扩展名脚本误当应用启动的问题。
- 总览改为 Agent 安装、模型选择、配置检查、进入智能体或创作的四步主旅程，并保留上次检查记录。

## 发布质量

- 增加 Agent、模型、手机矩阵和用户主旅程的高风险可靠性门禁。
- GitHub 官方 Actions 统一升级到 Node 24 兼容主版本，并通过桌面、手机和工作区全量 CI。
