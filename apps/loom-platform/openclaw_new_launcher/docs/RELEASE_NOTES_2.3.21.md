# LOOM 2.3.21 更新说明

## 手机连接

- 新增 USB 调试连接兜底：只保存手机令牌即可完成首次 USB 配置，不再要求先提供局域网地址。
- USB 连接必须明确确认，并且在多台 USB 手机同时存在时要求指定设备，不会猜测目标。
- 支持一键切回原局域网地址；没有局域网地址时可安全断开 USB，修改手机名称或地址不会破坏正在使用的 USB 通道。
- 自动安全探测手机端 `9527` 至 `9536` 的实际监听端口，并将签名身份挑战绑定到真实端口，兼容端口冲突后的手机端回退。
- 删除 USB 连接中的手机配置时会同步回收 ADB 转发，避免残留端口和后台占用。
- Bridge 启动后会在后台验证并重建所有已保存的 USB 通道，最多重试三次；页面恢复只负责展示状态。
- 启动恢复会先撤销 USB 凭据可信状态，并确认旧手机 daemon 已退出；无法确认退出时不会继续重建端口或发送令牌。
- 已连接 USB 手机重新验证时会先进入隔离状态，只有身份挑战成功后才重新开放给 Agent、Matrix 和 CLI。
- 连接、断开、删除和配置读取使用统一事务锁与原子配置写入，磁盘或清理失败不会留下假成功状态。
- ADB 转发表读取失败不再被误判为“已经断开”，自动选择设备后的真实序列号也会立即写入恢复事务。
- API 只返回必要的连接状态，不暴露 ADB 本地路径、执行明细或手机令牌。
- 新增无令牌 USB 身份挑战：先验证手机端 APK 与当前配置匹配，再通过新建通道发送任何凭据。
- USB 安全连接要求手机端 `6.62-stability`（`versionCode 931`）或更高版本；旧版会收到明确升级提示。

## 手机 Agent

- 将主仓库手机源码同步到已提交的 APKClaw `a7526e1e` 快照，补齐 6.54–6.61 期间已落地的确定性混合 RPA、动作账本、模板生命周期、轨迹编译、生产证据通道和可恢复评论任务。
- 手机端升级为 `6.62-stability`，保持与 6.61 相同的正式签名，可直接覆盖升级。
- 未导入外部仓库尚未提交的工作区改动，发布源码与构建结果可以复现。

## 矩阵控制

- 修复“最近任务”人工控制被错误判定为手机端不支持的问题。
- “最近任务”现在复用手机端 `system_key` 协议，与返回、主页等人工控制保持同一执行链路。
- 增加真实 CLI 快速通道合同测试，确保 Matrix 与 Agent 不会再次退回错误端点。

## 工程与安全

- 移除未使用的 `sharp` 构建依赖。
- 升级 `postcss` 并收敛混淆器传递依赖中的已知漏洞，`npm audit` 结果为 0。
- 修复 Python 测试包被第三方同名模块遮蔽的问题，完整测试可稳定收集。
- 修复 Node 合同测试偶发分配到 Fetch 禁用端口的问题。
- phone daemon 启动时会避开浏览器 Fetch 禁止端口，消除 Windows 随机分配 `10080` 时的偶发 `bad port`。
- 完成 Workspace、前端、Node、Python 和 Android 全链路回归。

## 升级说明

- 支持从 `2.3.20` 直接覆盖升级。
- 用户配置、模型账号、手机令牌、历史会话、本地素材和原局域网手机地址保持不变。
- USB 连接可独立使用，也可作为局域网连接的兜底；局域网连接正常时无需切换。
- 首次使用 USB 连接前，请先将手机端升级到 `6.62-stability`。
- 正在执行的手机或矩阵任务建议完成或停止后再升级。
