# 麓鸣 2.4.6 Windows Sandbox 小白逐按钮验收

本清单要求像第一次使用麓鸣的普通用户一样逐项点击。每一步记录“通过/失败/未测”、时间、截图文件名和可复现操作。不得因为页面能打开就判定业务成功。

## 0. 边界与证据

- 确认安装文件名包含 `2.4.6`，并核对 `installer-manifest.json` 中的 SHA256、字节数和签名状态。
- Windows Sandbox 不透传 USB；虚拟机内只能验证桌面流程和可达的 LAN 手机。真实 USB 枚举、拔插和六位码连接必须另在物理 Windows 主机补测。
- 支付只允许沙箱商户、测试账号或明确的零金额测试订单；不得进行真实扣款、退款或结算。
- 不在截图、日志或清单中记录授权码、API Key、PID、商户密钥、完整二维码令牌、手机号或用户隐私。
- 每个失败都保留当前页面、按钮、Toast、时间和复现步骤，不反复盲点同一个按钮。

## 1. 安装、品牌与版本

1. 在安装向导中逐页阅读并点击，不使用静默参数。
2. 确认产品只显示“麓鸣”，完整 Logo 清晰，启动动画保持原有设计。
3. 启动后打开设置或关于页，确认版本严格为 `2.4.6`，窗口标题、关于页、安装记录一致。
4. 关闭再启动一次，确认没有白屏、旧名称或旧版本号。

## 2. 登录与在线权威状态

1. 从未登录状态进入模型账户页，确认离线缓存明确标记为只读，不能绑定授权码、购买或同步模型。
2. 登录测试账户，点击唯一的在线验证入口，确认显示在线权威状态，而不是把 `default`、0 余额或旧快照冒充在线数据。
3. 核对套餐、模型、余额、用量、请求次数、邀请码、商业矩阵授权和各自到期时间。
4. 断网再刷新，确认页面显示“上次安全快照”及时间，写操作被禁用且原因可理解。
5. 恢复网络，确认状态重新变成在线权威数据。

## 3. Agent 安装与配置检查

1. 打开“安装智能体”，确认目录中只有 Codex Desktop，不再出现独立的 ChatGPT Desktop 行、按钮、计数或诊断。
2. 确认 Codex CLI 仍为单独一项，检测、安装和配置不与桌面端混淆。
3. 逐个点击刷新、详情、安装/升级入口；取消一次再重试，确认状态不会卡死。
4. 检查 Codex Desktop 的产品身份来自 `OpenAI.Codex`；程序入口叫 `ChatGPT.exe` 不能被误判为第二个产品。
5. 返回总览，点击配置检查，确认检查时间更新、模型凭据状态明确、错误给出下一步操作。

## 4. 绑定手机与手机矩阵

1. 从获客空状态分别点击“绑定手机”“打开手机矩阵”“选择模板”“排查连接”。
2. 在可用 LAN 手机上完成绑定手机，核对设备 ID、在线状态、任务状态和审计记录一致。
3. 确认“获客”与手机矩阵使用同一设备列表，而不是各自维护演示设备。
4. 在未授权账户点击矩阵与获客，错误只显示可操作中文，不显示 `acquisition.workbench` 等内部能力键。
5. 切换到有效 `matrix.devices` 账户，确认手机矩阵、基础获客、共享模板和 Skill 能力一起解锁。

## 5. 共享模板

1. 打开共享模板中心，新建一个仅含测试文本、没有隐私数据的模板。
2. 记录稳定 `template_id` 和版本；编辑后确认版本递增而 ID 不变。
3. 搜索、停用、启用、复制、删除前取消一次，再确认一次。
4. 在桌面 Agent、手机矩阵、获客任务和飞书流转中选择同一共享模板，核对版本一致。
5. 制造一次离线编辑/版本冲突，确认有冲突提示、缓存、重试与回滚，不静默覆盖。
6. 查看审计记录，确认敏感变量已脱敏。

## 6. Skill 中心与第二次调用

1. 打开 Skill 中心，检查列表、详情、来源、版本、适用 Agent、调用次数、最近使用时间和启停状态。
2. 让 Agent 首次完成一个无副作用的可复用流程，成功后在确认弹窗中选择沉淀为 Skill。
3. 关联上一节的共享模板，检查参数校验、权限边界、超时和审计信息。
4. 使用同样输入执行第二次调用，确认优先复用已验证步骤、脚本、模板和缓存，并记录两次耗时。
5. 停用后确认不能调用；重新启用后测试导出、导入和删除确认。
6. 在手机矩阵、获客和飞书中调用同一 Skill，核对调用统计同步。

## 7. 获客与飞书

1. 进入获客页，确认设备执行层来自手机矩阵，线索、草稿、人工确认和结果都有真实状态。
2. 使用共享模板创建测试获客任务，外发前必须停在人工确认。
3. 飞书只检查 OAuth、机器人、表格或文档连接条件，不要求第二份商业授权。
4. 断开飞书授权，确认显示连接修复步骤；恢复后重试同一任务，不产生重复记录。
5. 未经当前测试确认，不发送真实评论、私信、加好友或正式内容。

## 8. 套餐与扫码支付

1. 打开模型账户套餐区，核对真实套餐名称、价格、期限、权益和当前订阅状态。
2. 选择测试套餐和支付渠道，点击生成二维码；确认二维码内容与“浏览器打开”地址分别处理。
3. 重复点击生成，确认幂等订单不会重复创建或重复计费。
4. 未支付时点击“我已付款”，必须显示仍待确认，不能自行开通。
5. 关闭并重启麓鸣，确认重启恢复同一订单状态，但本地没有保存 PID、密钥、nonce 或完整二维码令牌。
6. 仅用支付商测试订单完成支付，确认 notify 验真后账户套餐刷新，并同步解锁矩阵、获客、共享模板和 Skill。
7. 测试重复通知和主动查单恢复；同一订单只能发放一次权益。
8. 同步返回页只能提示查询，不得直接显示或写入“支付成功已开通”。

## 9. 退出与切换账号

1. 在后台任务运行时点击退出，确认有明确提示且不会失控退出。
2. 停止任务后退出，再登录另一个测试账号。
3. 快速切换账号并连续刷新，确认旧账号响应不会覆盖新账号。
4. 返回原账号，确认本地会话、归档会话、索引、`config.toml` 和 `auth.json` 未被麓鸣删除。
5. 最后关闭应用并重新打开，确认账号、模板、Skill 和订单状态符合服务端权威数据。

## 10. 结束条件

- 所有必测步骤有结论；失败项有截图和可复现操作。
- `runtime-environment.json`、`installer-manifest.json`、`installer-result.json` 和人工清单均已保存到映射证据目录。
- Windows Sandbox 关闭后，再确认宿主机证据目录仍在。
- 虚拟机通过不能替代实体 Android、真实 USB、热点/Wi-Fi、Shizuku、MediaProjection、多机并发和长时间 soak 验收。
