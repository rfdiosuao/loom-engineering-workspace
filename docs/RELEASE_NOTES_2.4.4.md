# 麓鸣 2.4.4 / LumiAgent 6.65 发布候选说明

> 当前配套版本：麓鸣 Desktop `2.4.4`；LumiAgent `6.65-stability`（Android 7 为
> `6.65-stability-android7`）；手机 `versionCode` 为 `934`。

## LumiAgent 6.65 新增

- 新增首屏可达的 **Skill 中心**，统一展示内置 Linux Skill 与 Agent 学习沉淀的工作流。
- 成功的只读、直接动作可在第一次执行后安全激活，第二次直接进入确定性快速路径；所有副作用、
  视觉定位和结构选择器流程继续遵循多轮验证门禁。
- 新增独立安装的 `Lumi Linux Runtime` 伴随 APK：PRoot `5.1.107.89` + Alpine
  `3.22.5`，仅接受固定 Skill ID 和固定操作，不开放任意脚本、可执行路径或参数向量。
- Linux 伴随 APK 不申请 `INTERNET` 权限，主 APK 与伴随 APK 通过签名级权限通信；安装采用
  SHA-256/SBOM 校验、staging、健康检查、原子切换与失败回滚。

## 版本

- 麓鸣 Desktop `2.4.4`
- LumiAgent `6.65-stability`，versionCode `934`
- Android 7 兼容变体：`6.65-stability-android7`，versionCode `934`

本轮产品名称统一为“麓鸣”。桌面窗口、安装包产品名和应用内品牌不再使用“麓鸣AI矩阵获客工作台”等局限性名称；完整麓鸣 Logo 已恢复，启动界面原动画保持不变。

## 主要变化

### 手机连接与设置

- “与麓鸣配对”“连接方式与局域网”“连接诊断”移动到手机设置第一组；仅移除“发布中转”用户入口，正式发布协议、授权、频控和审计链仍保留。
- USB、LAN、Wi-Fi 客户端和手机热点拥有明确状态；用户关闭局域网服务后，旧网络回调不能把服务重新拉起。
- USB 模式始终显示六位一次性配对码，不再因为手机同时连接 Wi-Fi/热点而隐藏。
- Desktop 连接档案、ADB forward、LAN 地址探测和降级原因可解释；失联与重连不会复用过期 transport 状态。

### 聚焦手机低延迟视频

- 新增 MediaProjection + MediaCodec H.264 低延迟视频通道，仅用于当前聚焦设备；USB forward 与视频流是两层独立能力。
- Desktop 通过本机一次性 ticket 建立 WebCodecs 解码通道，不把手机长期 token 暴露给前端。
- 帧队列采用丢旧保新；视频权限拒绝、编码器或浏览器解码不可用时自动退回截图预览，不阻塞任务、控制和急停。
- 矩阵非聚焦缩略图仍采用自适应截图，不把多机截图轮询表述为“实时视频”。

### Agent、账号与界面恢复

- 完整麓鸣 Logo 使用随包资源并带安全回退；侧栏、账户卡片和空会话不再重复堆叠同一个品牌标记。
- 模型账号页区分在线数据、上次快照和服务未返回，不再伪造 `default` 套餐或把缓存刷新误报为在线成功。
- 未激活商业矩阵授权时，在创建会话、编辑器和发送入口统一前置拦截；拒绝结果不再留下幽灵会话，也不泄露内部错误码。
- ChatGPT、Codex Desktop、Codex CLI 拆分识别；即使 Codex Store 包入口名为 `ChatGPT.exe`，也不会误判为 ChatGPT Desktop。
- Agent 目录纳入 Grok Build、Pi、Goose 等独立组件身份和兼容性探测；原始检测路径收纳进高级详情，默认界面使用中文结论。
- 登录账号发生变化时旧账号 Agent 实例必须先安全排空；停止结果异常、类型错误或无法确认时失败关闭，避免旧账号运行态跨账号泄漏。
- 麓鸣中转站 Base URL、Key、模型配置采用兼容性 probe、staging/commit 和失败回滚；敏感值只写不读，不覆盖健康的官方账号配置或历史会话。

### 可靠性闭环

- 账号切换使用 epoch/事务门禁，旧账号异步结果不能覆盖新账号；切换期间矩阵拒绝创建新任务。
- 正式发布要求本次操作的新证据并在完成阶段复验短期授权令牌，避免遗留成功页和过期 token 误报成功。
- 图片/视频下载失败、畸形 HTTP 200、部分批次和结果不确定场景不再自动重生成，避免重复调用或重复计费。
- 更新备份失败时尝试重新启动旧版本；附件持久化失败会清理本次孤立文件；模型服务错误分类补齐超时、5xx、Cloudflare、DNS 和连接重置。
- Windows CLI 改用只读 Win32 进程状态探测，避免退出进程被误判存活或 `os.kill(pid, 0)` 包装异常导致命令失败。

### Shizuku 增强能力

- 接入官方 Shizuku API/Provider `13.1.5`，用户必须在本机主动开启并通过 Shizuku 官方授权。
- 未安装、停服、binder 断开、拒绝或撤权时自动保持标准模式，不影响配对、LAN/USB、RPA、截图和急停。
- Root/Sui 默认禁用；不内嵌 Shizuku、不包含 `rish`，不向模型、LAN 或第三方 Agent 开放任意 Shell/命令执行。
- 2.4.4 只交付探测、授权和类型化策略边界，尚未把增强动作接入远程生产 API。

### PRoot/Linux 兼容运行时

- 商业主 APK 不内置 PRoot/rootfs；本轮提供可独立安装和卸载的 Linux companion 本地测试候选。
- companion 包含经哈希锁定的 PRoot 5.1.107.89、Alpine 3.22.5、SBOM 与许可证说明，无 INTERNET 权限，只开放两个固定文本处理 Skill。
- API 36 与 API 24 虚拟机已完成真实冷安装和连续执行；这只能证明本地候选可运行，不能替代实体机性能、温升、故障恢复和商业发行门禁。

## 数据与账号保护

- 切回官方账号不会删除同一电脑上的 `sessions`、`archived_sessions`、会话索引、本地状态数据库、原 `config.toml` 或原 `auth.json`。
- 所有新增 scope、审批、幂等和 trace 记录均避免写入 Key、token、命令正文、用户附件内容或可逆设备标识。

## 已知限制与实体机验收

- 自动化测试与 Android 虚拟机不能替代实体机验收。USB 聚焦视频 30 分钟、20 次拔插、热点/Wi-Fi 切换、Android 7/10/14+、2 台并发与 10 台两小时 soak 仍需真实设备证据。
- Shizuku 的 Android 7-10 电脑 ADB 启动、Android 11+ 无线调试、停服/升级/撤权/重启恢复仍需实体机验收。
- 可选 PRoot/Linux companion 已生成独立本地调试候选，但尚未通过对应源码交付、法律、商业签名和实体机性能门禁，因此不进入正式更新通道。
- 本地候选可在没有商业代码签名的情况下用于受控测试，但不能表述为正式签名发布包；APK release 构建必须匹配仓库信任指纹。

本任务只生成本地发布候选。未经明确确认，不推送正式更新通道、不创建正式 Release、不上传安装包，也不执行任何对外发布、评论或消息动作。
