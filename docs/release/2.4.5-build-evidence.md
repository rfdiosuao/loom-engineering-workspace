## 2. 功能结果

- Agent 安装目录只保留 Codex Desktop，并按 `OpenAI.Codex` Store 包识别；程序入口名 `ChatGPT.exe` 不再产生第二个 ChatGPT Desktop 产品。Codex CLI 保持独立。
- 有效 `matrix.devices` 是手机矩阵、基础获客、飞书流转、共享模板和 Skill 的唯一商业授权。飞书 OAuth/机器人/表格/文档权限只是连接条件，不再要求第二份商业授权。
- 商业能力目录只保留 `matrix.devices` 一个付费键；`acquisition.workbench`、`acquisition.feishu` 与 `templates.cloud` 不再作为可拆卖授权项。`/api/matrix/acquisition`、飞书、共享模板和 `/api/skills` 路由均映射到同一矩阵授权。
- 共享模板使用稳定 `templateId` 与版本号，具备搜索、启停、冲突检测、离线缓存、重试、回滚、审计和敏感变量脱敏。矩阵高级任务抽屉可直接读取并选择启用模板，按 `loom.matrix.dispatch.v2` 把版本引用送到每台手机。
- 后端会在有无自定义任务描述两种情况下解析并校验共享模板；不存在、停用和版本冲突均返回稳定客户端错误，禁止把错误版本悄悄当成普通 Agent 元数据执行。模板元数据贯穿内容任务、线索、客户、草稿、手机 Agent 任务和飞书来源任务。
- 桌面 Skill 中心具备列表、详情、版本、来源、适用 Agent、调用统计、启停、导入导出和删除；Skill 可在沉淀时或详情页绑定共享模板的精确 `templateId + version`，执行时重新校验模板仍启用且版本一致，版本过期会拒绝执行并要求重新绑定。手机 Skill 继续使用固定白名单操作与首次沉淀、再次快速复用路径。
- 模型账户页面明确区分在线权威状态和只读安全快照；账号切换时以请求版本和过渡锁阻止旧响应覆盖新账号。
- Z-Pay/易支付实现后端 Provider Adapter、Decimal/整数分金额、先落 `pending`、幂等请求、签名校验、nonce、商户/订单/金额/渠道/流水校验和同事务权益发放。桌面端不保存 PID 或密钥，二维码只从 `qrcode` 生成，`payUrl` 只用于外部跳转，不再把支付链接回退编码成二维码；同步返回页不会开通权益。
- 支付渠道不再硬编码：套餐接口只返回 `LICENSE_ZPAY_CHANNELS` 中经白名单校验且真实启用的渠道。生产商户当前只启用 `alipay`，因此桌面端不会展示微信支付；即使客户端伪造 `wxpay` 请求，服务端也会在创建 `payment_orders` 记录前拒绝。
- 二维码过期或订单确认支付后都会清除二维码内容与跳转 URL；重复成功回调也会清理历史残留令牌，已验真的迟到回调仍可幂等入账。应用重启只恢复账号、套餐、渠道、幂等请求 ID 和订单 ID，不把二维码、支付链接、nonce 或商户资料写入 `localStorage`。
- “我已付款”可显式触发服务端主动查单；仅当支付商返回的商户、订单、金额、币种、渠道、nonce、商品和唯一流水全部匹配时才复用同一事务发放权益。后台轮询只读本地订单，不会持续携带商户密钥查单。
- 支付能力和主动查单均默认关闭；候选包没有真实商户域名、PID 或密钥。未提供并沙箱核验生产商户配置时不会发起真实订单。

## 6. 尚未开放的生产门禁

1. Windows 安装包没有商业 Authenticode 签名，Android 主 APK 与 companion 仍为调试签名。
2. 未把 Z-Pay 商户密钥安全迁移到授权服务，也未核验生产回调可达性，因此支付 Provider 与主动查单保持关闭；没有执行真实扣款、退款、结算或商户资料修改。2026-08-02 的授权服务只读存在性检查确认旧版 9 个 `LICENSE_ZPAY_*` 配置键均缺失，线上授权服务也尚未部署支付路由模块；检查只输出 `configured/missing`，没有读取任何值。
   2026-08-03 对既有中转站的只读审计确认 Z-Pay 商户配置已经存在，公开支付地址为 `https://zpayz.cn`，支付方式仅为 `alipay`；商户号与密钥没有输出。复用这套商户配置仍属于生产密钥迁移和服务切换，必须另行确认并走备份、门禁与回滚。
   已生成可回滚、无密钥的 r4 生产候选 ZIP，但没有把它上传或部署到生产机；这不等于真实扫码支付已经上线。
3. 回调丢失后的服务端主动查单与严格二次核验已经实现并通过本地集成测试；仍须使用该商户自己的沙箱/测试账号验证真实 `mapi.php`、`api.php`、notify 和确认回执后，才能启用 `LICENSE_ZPAY_QUERY_ENABLED=1`。
4. Windows VM、实体 Android 手机、真实 USB 枚举/拔插、热点/Wi-Fi、MediaProjection、Shizuku Binder、温升、多机并发和长时间 soak 尚未完成。
5. PRoot companion 正式商业分发仍需发布签名、许可证/源码提供、CVE/EOL、实体机性能和回滚门禁。
6. 本轮只提交并推送功能分支；不合并 PR、不更新正式下载通道、不创建正式 Release。

因此这些文件是可复测的本地候选，不代表生产支付和正式发布已经完成。
