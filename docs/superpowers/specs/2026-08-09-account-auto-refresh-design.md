# Account 页面自动刷新与静默快照设计

## 目标

用户打开“模型账户”页面时自动获得当前最新的账户、余额、套餐与授权状态，不再看到“上次安全快照”横幅、“上次快照/在线数据”标签或“重试在线验证”按钮。

## 行为

- 页面首次挂载时立即显示已有安全快照，避免空白和布局跳动。
- 同时自动触发现有在线账户刷新流程；成功后用服务端最新结果替换快照。
- 同一页面生命周期内避免并发重复刷新；用户离开后重新进入可再次刷新。
- 在线刷新失败时保留最后一份安全快照，不弹出页面级黄色横幅，也不要求用户手动重试。
- 没有任何可用数据时，在对应数据卡片内显示简短不可用状态，不伪造余额、套餐或授权结果。
- 商业授权继续以服务端签名数据和现有授权校验为准；本改动只调整呈现与刷新触发，不降低 fail-closed 约束。

## UI 变更

- 删除页面级“当前显示上次安全快照”警告横幅。
- 删除顶部及横幅内的“重试在线验证”按钮。
- 删除余额区域的“上次快照/在线数据”状态标签。
- 保留“模型选择”“刷新余额”“刷新套餐”“打开账户中心”等与具体业务动作相关的入口。
- 自动刷新失败不再用大面积提示打断用户；已有字段继续显示最后可用值，缺失字段显示“服务暂未返回”。

## 数据流与错误处理

1. 页面挂载，读取当前 store/cache 快照。
2. 调用现有在线账户刷新接口，不新增旁路授权接口。
3. 成功：原子更新账户、订阅、余额和授权视图。
4. 失败：保持快照，记录现有内部错误状态供诊断，不渲染页面级快照警告。
5. 页面重新进入：重新执行一次在线刷新，确保不是永久使用旧数据。

## 验证

- 源码合同测试确认三个快照提示入口和手动验证按钮已移除。
- 测试确认页面挂载仍自动调用在线刷新逻辑。
- 测试确认缓存数据仍可作为失败降级，不因隐藏提示而清空。
- 运行 Account UI 定向 Python tests、TypeScript typecheck 与 Platform contracts。

## 非目标

- 不增加周期轮询。
- 不改变服务端计费、套餐或授权规则。
- 不删除诊断日志或内部缓存状态。
- 不把缓存数据升级为可信在线授权结果。
