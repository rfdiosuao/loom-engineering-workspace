# LOOM 2.4.0 Agent 与模型发布准备审计

审计日期：2026-07-29

审计范围：LOOM 原生中枢智能体、模型路由、手机安全配对与恢复、Skill 安装、自动更新退出交接、全局语义颜色和仓库发行门禁。

## 结论

`2.4.0` 已达到代码级生产候选标准。自动化验证没有发现未解决的 P0/P1 缺陷，且本轮对抗审查发现的凭据宽限、旧接口暴露、确认重试耗尽、Agent 终态分裂、Skill 目录误删和更新器提前退出问题均已修复。

本结论不替代实体手机、真实模型供应商、十机长稳或商业代码签名验收。完成这些外部环境测试前，版本可以用于受控灰度，不应宣称所有公网和硬件场景已经验证。

## 关键闭环

### 手机配对

- 用户界面不再要求查看或输入长期 `apiToken`。
- USB 使用 6 位短时一次性配对码；局域网使用包含高熵引导密钥的完整配对信息。
- 长期凭据由协议自动交换，并分别使用 Windows DPAPI 和 AndroidKeyStore 保护。
- 成功配对后旧凭据只保留 30 分钟迁移宽限。
- 旧版配对接口仅允许 USB 回环访问，完成安全配对后永久关闭。
- 桌面按设备退避并低频持续确认新凭据，临时断线不会永久耗尽恢复次数。

### 中枢智能体

- 模型、工具、审批、暂停、取消、恢复和终态继续复用 LOOM 原生 Harness。
- 最终回复与运行完成状态通过写前事务一起提交；崩溃恢复幂等，不产生重复回复或假完成。
- 工具调用按运行聚合，终态不会被迟到事件回退。
- 写操作保持精确目标、作用域、授权、审计和至多一次执行语义。

### Skill 与更新

- Skill ZIP 使用固定条目顺序、时间戳、权限和压缩参数，产品构建 SHA256 为 `0120B6D2F81B0FADE00DB4C6791570B3BD5D64B9DA6BB97CC0FAB8404C5857D0`。
- Skill 安装器只清理带完整 LOOM 所有权标记的事务目录，保留名称相似的用户和第三方目录。
- 桌面更新移交会等待 Bridge 完成 Agent 排空并释放 Node/Python 运行时，再退出桌面进程。

### 视觉一致性

- 总览、安装、智能体、创作、获客、矩阵、模型、设置和诊断共用同一语义色系统。
- 亮暗主题关键文本和按钮状态达到 WCAG AA。
- 弹窗支持焦点进入、循环、Escape 关闭和焦点恢复。

## 仍需外部验收

1. Windows 10/11 干净机上的 Codex、Claude Code 和 OpenCode 安装、启动与中文首轮对话。
2. LOOM 托管中转站、自定义中转站和 BYOK 的真实成功、无权限、模型下线、`503/504` 与超时场景。
3. 一台及多台实体手机的 USB/LAN 首配、重启恢复、拔插、IP 漂移、弱网和凭据轮换。
4. 十台实体手机两小时 Matrix 截图、任务、急停与恢复综合 soak。
5. 真实生图、生视频、素材传输和外部平台发布。
6. 商业可信 Authenticode 证书和正式桌面更新签名私钥。

## 灰度建议

先向内部账号和少量真实用户发布，持续观察安装完成率、模型配置完成率、首轮对话完成率、配对成功率、恢复耗时、上游故障占比和售后工单。任何 P0/P1 回归立即停止扩量并回滚，不以新增功能掩盖基础链路问题。
