## 结论

LOOM 当前已经是单仓库工程，平台、手机 Agent、共享合同、Skills 和开发文档都在同一条主线上。历史线程里的 `2.1.x` 版本、旧仓库路径和未更新的 Epic 勾选项不能继续作为当前事实源。

原生智能体、手机矩阵、全案九步、生图生视频、素材库与手机传输、模型账号、更新回滚、中文交互和仓库治理均已有生产实现与自动化测试。本轮没有发现需要推倒重做的架构问题。

## 本轮闭环

1. 打通 Matrix “最近任务”按钮到手机端 `system_key(recent)` 兼容接口，删除旧的硬编码“不支持”分支。
2. 移除未被工程引用的 `sharp` 构建依赖。
3. 将 `postcss` 升级到已修复版本，并覆盖混淆器旧 glob 依赖中的易受攻击 `minimatch` 版本。
4. 增加内置 ADB 的 USB 连接兜底，支持显式设备选择、独立回环转发、恢复局域网连接和删除时清理。
5. 为手机连接、断开、删除和配置读取增加统一事务锁；配置改为同目录临时文件、`fsync`、原子替换，失败补偿会返回真实结果。
6. USB 身份绑定必须匹配 APKClaw 状态契约；公共接口、ADB 诊断和持久配置响应均不暴露令牌、ADB 路径或原始命令明细。
7. 首次纯 USB 配置不再依赖局域网地址；Bridge 启动后后台验证并重建全部已保存转发，按手机真实监听端口在 `9527` 至 `9536` 间安全发现。
8. ADB 转发表读取失败与“没有转发”严格区分，自动选中设备后的序列号会写入恢复事务，避免清理失败被误报为成功。
9. 隔离 Python 测试包，避免被环境中的第三方同名 `tests` 包遮蔽；修复 Node 测试随机分配到 Fetch 禁用端口的偶发失败。
10. 发现主仓库手机源码停留在 6.53、实际发布包已到 6.61 的漂移；以不可变上游提交 `a7526e1e` 同步已提交源码和测试，并叠加 6.62 安全 USB 身份挑战。外部工作区未提交内容未被导入。
11. USB 重新验证会先持久化撤销身份可信状态，只有挑战成功才恢复；Bridge 启动恢复会先隔离 USB 凭据，并确认旧 phone daemon 已退出，无法确认时直接阻断恢复。
12. phone daemon 动态监听会主动避开 Fetch 禁止端口，解决 Windows 偶发分配 `10080` 后客户端无法连接的问题。
13. 将本审计加入开发 Wiki，作为跨线程判断“已完成 / 未完成 / 已过时”的当前入口。

## 仍需真实环境验收

以下项目不能仅凭代码或模拟器宣布完成，应在发布候选包上保留实机证据：

1. 至少 10 台实体手机持续 2 小时的 Matrix 并发、截图、下发、急停和恢复测试。
2. 每个实际售卖模型供应商的登录、对话、生图和生视频成功率统计。
3. 抖音、小红书等目标 App 在不同版本、分辨率和厂商系统上的发布流程验收。
4. 飞书真实租户的线索写入、字段映射、权限失效和重试验收。
5. Windows 安装、覆盖升级、失败回滚、卸载和残留进程的干净机矩阵。

这些属于发布验收，不应重新拆成另一套平行架构。
